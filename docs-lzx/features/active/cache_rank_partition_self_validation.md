# Cache Rank Partition 改动清单与自验证报告

## 分支包含的改动

- 分支：`codex/cache-rank-partition`
- 当前整理基线：`895312e0`
- 对比基线：UCM `v0.7.0`
- 性能数据：2026-09-17、2026-09-18 的实测记录；当时的精确测试 commit 未单独记录

该分支主要包含以下改动：

1. **SDMA Direct 多 stream**：支持 `cache_stream_number` 配置，SDMA Direct 默认使用 16 个 stream，提高聚合 H2D 的并行度。
2. **CacheBuffer 重构**：以统一 Buffer 替换旧 TransBuffer，控制区与 KV 数据区分离；控制区维护索引、slot 状态、引用计数和 CLOCK 信息，数据区只保存 KV payload。
3. **桶锁与 slot 元数据并发优化**：命中路径优先使用乐观查找和原子 pin，减少 bucket 锁竞争；bucket 锁分条复用，slot 热点字段按 cache line 隔离，降低 false sharing 和槽位申请开销。
4. **按 Rank 分块 SHM**：共享控制区保持全局一致，KV 数据区按 rank/segment 划分；分配优先落在目标 segment，容量不足时可跨段回退，每段独立维护 CLOCK 指针。
5. **多 Rank 访问顺序优化**：Load/Dump 根据 rank 调整访问起点，使并发 worker 优先访问不同数据段，减少同一内存控制器上的流量集中。
6. **NUMA 绑定策略**：在 first-touch 前执行绑定，并支持页面落点校验；补充 NPU/CUDA 拓扑识别、GQA/MLA 差异化策略，以及 FAWA/HLA 配置传递。
7. **正确性与稳定性修复**：修复 Prealloc 后 Owner 选举、in-flight slot 可见性、共享段初始化等待和清理等问题，并补充 NUMA/拓扑与并发回归测试。
8. **配套基础优化**：包含线程池唤醒优化和 Posix Load 提交解耦，降低调度路径上的额外开销。

说明：Lookup 触发的首层预取曾在开发过程中进入该分支，最终已拆出，不属于当前 `codex/cache-rank-partition` 的交付范围。

以下指标均为 TTFT，单位 ms，数值越低越好。“变化”按优化后相对优化前计算。当前记录未包含多轮均值或分位数，因此小幅差异按波动处理。

## 结论

- **主提升场景是 A3 + MLA + Cache 命中**：GLM-5.1 32K/64K TTFT 分别下降 12.2%/20.6%，收益明确。
- A3 MiniMax 场景有小幅提升；A2 DSV4 场景存在正负波动，其中 32K/64K 当前样本有劣化。
- 因此可以确认目标场景有效，但“任意 UCM PC 场景无劣化”尚未完全证明。建议对 A2 波动项进行多轮复测，再给出最终验收结论。
