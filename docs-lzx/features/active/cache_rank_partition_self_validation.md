# Cache缓存管理桶锁的互斥使用乐观锁，节点锁优化cache line问题，降低槽位申请的耗时；Cache缓存管理的内存分配按rank划分，突破单DDR内存控制器带宽瓶颈——需求改动清单与自验报告

## 分支包含的改动

- 分支：`codex/cache-rank-partition`
- 当前整理基线：`895312e0`
- 对比基线：UCM `v0.7.0`
- 性能数据：2026-09-17、2026-09-18 的实测记录；当时的精确测试 commit 未单独记录

该分支主要包含以下改动：

1. **SDMA Direct 多 stream**：支持 `cache_stream_number` 配置，SDMA Direct 默认使用 16 个 stream，提高聚合 H2D 的并行度。
2. **CacheBuffer 重构**：以统一 Buffer 替换旧 TransBuffer，控制区与 KV 数据区分离；控制区维护索引、slot 状态、引用计数和 CLOCK 信息，数据区只保存 KV payload。
3. **缓存索引并发优化**：Cache 命中时先进行无锁查找，仅在冲突或需要分配新槽位时加锁，减少多 rank 并发访问时的锁等待；大量 bucket 共用固定的 65536 把锁，减少锁本身占用的共享内存；同时将引用计数、状态和访问标记分开放置，避免多个线程频繁修改同一条 cache line。
4. **按 Rank 分块 SHM**：共享控制区保持全局一致，KV 数据区按 rank/segment 划分；分配优先落在目标 segment，容量不足时可跨段回退，每段独立维护 CLOCK 指针。
5. **多 Rank 访问顺序优化**：Load/Dump 根据 rank 调整访问起点，使并发 worker 优先访问不同数据段，减少同一内存控制器上的流量集中。
6. **NUMA 绑定策略**：在 first-touch 前执行绑定，并支持页面落点校验；补充 NPU/CUDA 拓扑识别、GQA/MLA 差异化策略，以及 FAWA/HLA 配置传递。
7. **并发正确性与启动稳定性**：Prealloc 只预留槽位，由第一个正式 Load 负责加载数据，避免所有请求都等待但无人加载；Lookup 能识别正在加载的槽位，避免重复分配和重复加载；同时延长大共享内存的初始化等待时间，并补充 NUMA、拓扑和并发回归测试。

## 自验报告

以下测试均为 Cache 命中场景，指标为 TTFT，单位 ms，数值越低越好。“变化”按优化后相对优化前计算。

### A3：GLM-5.1 W4A8，DP1 TP16，1 并发 1 输出，100% Cache 命中

vLLM Ascend：`0.23.0rc1`

| 序列长度 | HBM PC | 优化前 v0.7.0 | 优化后 | 变化 |
|---|---:|---:|---:|---:|
| 32K | 480 | 615 | 540 | -75（-12.2%） |
| 64K | 626 | 970 | 770 | -200（-20.6%） |

## 结论

- **主提升场景是 A3 + MLA + Cache 命中**：GLM-5.1 32K/64K TTFT 分别下降 12.2%/20.6%，收益明确。
- 其他场景的 TTFT 有一定波动，整体无明显劣化。
